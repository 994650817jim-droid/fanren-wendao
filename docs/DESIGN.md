# 《凡人问道》设计文档

> 版本 v0.2.0 · 阶段一修复版（Phase 1.1）
> 定位：单人文字修仙 RPG + 放置成长 + 随机奇遇，纯前端，零成本运营。

---

## 1. 核心循环

```
创建角色 → 闭关（产修为） ／ 凝灵（产灵石） → 修为满 → 突破境界（有保底的风险）
        → 境界提升（气血/寿元/属性成长） → 继续修炼 …… → 金丹初期 → 阶段三接最终 Boss
```

**行动成本统一**：闭关、凝灵、突破都消耗游戏时间；玩家在「修为」「灵石」「寿元」三者之间做取舍。

**规则**

- 闭关：`修为 += 境界基础 × 灵根 × 天赋 × 3 个月 × random(0.85, 1.15)`，满即封顶；**满时不可闭关**
- 凝灵：`灵石 += 5 × random(0.9, 1.3)`（**固定值，不随灵根缩放**），消耗 3 个月，不产修为
- 突破成功率 = `境界基础 + 天赋加成 + 软保底`，夹在 5% ~ 100%
- 突破失败：修为 -25%（按上限）、气血 -20%（保底 1）、耗时 +6 个月。不掉境界、不死亡。
- **软保底**：同一境界每失败一次，下次成功率 +5 个百分点；连续失败 5 次后，下一次必定成功。计数写入存档，成功后清零。

## 3. 灵根与天赋

| 灵根 | 修炼/凝灵系数 | 权重 |
|---|---|---|
| 天灵根 | ×1.5 | 5 |
| 双灵根 | ×1.2 | 25 |
| 三灵根 | ×1.0 | 40 |
| 五行杂灵根 | ×0.8 | 30 |

凝灵收益与灵根无关（固定 5 点）：灵根只决定修炼快慢，资源获取交给独立属性（阶段二接历练）。否则「灵根好 = 修炼快 + 赚钱快」，差灵根会被双重惩罚。

| 天赋 | 修炼 | 突破加成 | 气血 |
|---|---|---|---|
| 修炼天才 | ×1.25 | +0% | ×1.0 |
| 炼丹奇才 | ×1.05 | +2% | ×1.0 |
| 福缘深厚 | ×1.0 | +5% | ×1.0 |
| 体魄强健 | ×1.0 | +0% | ×1.2 |
| 资质平平 | ×1.0 | +0% | ×1.0 |

## 5. 存档结构（v2）

```json
{
  "version": 2,
  "savedAt": "2026-11-09T12:00:00.000Z",
  "character": {
    "name": "测试道友",
    "rootId": "triple",
    "talentId": "genius",
    "realmId": 1,
    "exp": 0,
    "hp": 110,
    "stones": 20,
    "months": 207,
    "pity": { "9": 2 },
    "log": [{ "month": 207, "text": "……", "kind": "milestone" }]
  }
}
```

**迁移**：`MIGRATIONS` 表按版本逐级升级；v1 → v2 补 `pity: {}`。迁移或校验失败 → 拒绝导入、保留原存档、提示具体原因。

## 6. 架构约定

- `src/data/` 只放数据表；`src/core/` 纯函数、零 DOM；`src/ui/` 只渲染。
- **所有改变游戏状态的行动都走 `resolveAction(character, action, rng)`**，返回 `{ ok, error, events }`；UI 不允许直接改 `character` 字段。
- 随机数通过 `rng.js` 注入，测试与模拟可用固定种子复现。
- 日志由行动结算产生，导入的日志文本按纯文本渲染，不写 `innerHTML`。

## 8. 阶段二开工前要定的三条规则

1. **金丹不是终点**：金丹初期之后仍可凝灵、历练、装备、挑战 Boss；只有击败最终 Boss 才进通关结局。当前 UI 的「已是终点」只表示修为不能再涨，阶段三会改成「待挑战」。
2. **战斗失败不永久死亡**：默认 = 受伤 + 损失部分灵石 + 强制返回洞府。若要加寿尽/身死，作为独立规则单独设计，不在战斗默认流程里。
3. **寿元是硬约束但阶段一不施压**：到上限即「道消」结局（已实现）。压力由阶段二的历练耗时、重伤扣寿元引入；阶段一不削寿元上限。

## 9. 阶段二仍需偿还的技术债

1. 历练、战斗、背包必须走 `resolveAction`，不允许绕过。
2. 凝灵应降为「低效兜底」，历练成为灵石主来源。
3. 30 个奇遇需要事件数据结构（条件 / 选项 / 结果）与可测试的随机选择。
4. 多一条状态校验：进入战斗前写「战斗快照」，异常退出后可恢复，避免战斗中断导致状态损坏。

## 10. 突破最终概率表（13 档，唯一权威计算）

`finalChance = clamp(baseChance + talentBonus + pityBonus, 0.05, 1)`，其中
`pityBonus = min(pity, 5) × 0.05`；当 `pity >= 5` 时**直接返回 1**，不再进入 clamp。
境界表里的 `rate` 已经是最终基础值，**不存在额外的大境界惩罚字段**，不会二次扣减。

## 11. 状态契约（阶段二必须遵守）

1. **原子性**：行动被拒绝（条件不满足 / 未知行动）时，角色对象**一个字段都不改**，有 `integrity.test.js` 断言。
2. **一次性结算**：时间、资源、属性、日志在同一次 `resolveAction` 内一起变化，UI 只渲染返回的 `events`。
3. **保存在动作之后**：`autosave` 失败必须提示，不允许静默丢弃；导入失败不得覆盖内存中的角色。
4. **寿元临界**：凝灵可以解决「灵石不足」，但**不能**解决寿元耗尽。当剩余寿元不足以支撑一次行动并因此进入「道消」时，这是**合法结局**，不是程序软锁；模拟统计里单列。
5. **pity 合法范围 0–5**：超出即视为异常存档，读档时夹到 5；成功后清零；失败每次 +1。

## 12. 阶段二切片：历练与奇遇（v0.3.0）

### 历练规则

- 每次消耗 3 个游戏月
- 先结算保底灵石：`4 + random(0..3)`，是灵石的主要来源（凝灵降为兜底）
- 然后按境界抽奇遇：`event.minRealm <= character.realmId` 的事件池，按 `weight` 加权
- 历练与奇遇**都不会致死**：气血最低 1

### 奇遇数据结构

```js
{
  id, title, desc, minRealm, weight,
  choices: [{ id, text, outcomes: [{ weight, text, effects: [...] }] }]
}
```

效果类型（`core/explore.js` 统一结算）：
`{type:'exp', ratio}` 修为按境界上限比例；`{type:'stones', value}`；`{type:'hp', ratio}` 气血按上限比例（保底 1）；`{type:'months', value}` 额外耗时。

### 当前内容量

10 / 30 条。已有：神秘洞府、遇见高人、灵兽袭击、灵草采集、遭遇劫修、宗门邀请、捡到法宝、危险秘境、修士交易、发现功法。
